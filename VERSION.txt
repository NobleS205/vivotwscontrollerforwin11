VivoPods Controller
===================

显示版本（关于页显示）: V11.45.80
构建版本（本包标记）  : v3.31
构建时间             : 2026-10-29 23:13 (GMT+8)

本包内容为 v3.31，包含：
  - 显示版本号改为 V11.45.80（关于页 / appmeta.py / README 统一）
      · 功能与 v3.30 完全一致，仅版本号更新
  - vivo / iQOO 型号能力表补齐到 41 个（官方 tws_config.json 全量）
      · 此前只覆盖 25 个，剩下 16 个被当成「未知型号」乐观全开，
        导致 TWS Air / Air2 / Air3 / A1~A5 / Neo / 5i 这些没有 ANC 的
        耳机也显示「降噪 / 关闭 / 通透」
      · 现在型号名与能力只维护一份（vivo_models.MODELS），不再两份表各抄一遍
  - 新增 tools/vivo_audit.py：一条命令打印全部型号能力表、明确不支持清单、
    每项功能的实现状态与真机风险；--doc 生成 docs/VIVO_SUPPORT.md
  - 降噪兜底收紧：只有耳机真回报「降噪 / 通透」才补出分区，只回「关闭」不算
  - 降噪分区以耳机回报为准（v3.29）：名字带后缀 / 被改名也能正常显示
  - 面板刷新容错：换实物图、重建 EQ 失败不再连带藏掉整块功能区
  - TWS 3e 双连修正：该型号双连硬件常开，不再显示空的多设备分区、也不再空查
  - 后台常驻：面板收起、挂机数小时也不会自己退出
      · 槽函数 / 后台线程 / 析构里的异常只写日志，不再结束进程
      · 原生崩溃写 crash.log（faulthandler），可查可定位
  - 崩溃自愈：独立看门狗盯着主进程，检测到崩溃痕迹就自动拉起一次
      · 被任务管理器 / 安全软件强杀时不重启（手动杀死就是真死）
      · 1 小时内最多拉起 3 次，避免「一启动就崩」的死循环
  - 托盘自愈：Explorer 重启把图标弄丢时，20 秒内自动重新挂载
  - 单实例：重复双击只唤出已有面板，不再起第二个托盘 / 看门狗
  - 日志（%LOCALAPPDATA%\VivoPodsCC\）：runtime.log（启动 / 退出 / 每 10 分钟
    心跳 + 内存占用 + 连接时的型号与能力）、crash.log、watchdog.log
  - vivo 耳机在仓充电图标：放回仓、开盖连接时左右耳也显示充电闪电
  - 新增 tools/battery_probe.py：抓取 vivo 电量 / 佩戴原始报文用于排查
  - 断连 1~3 秒内更新；切换设备立即清空旧读数
  - 连接后主动查询佩戴状态（不必摘戴一次）
  - FreeClip 2 佩戴支持左右耳区分（左耳未佩戴 / 右耳未佩戴）
  - FreeClip 2 连接时耳机图标切换为其实物图
  - 关于页只显示居中的「关于」，返回后佩戴 / 连接状态回到原位
  - 二级菜单：演示模式合并为子菜单；移除「折叠面板」「固定浮窗」
  - 折叠动画到点强制落位（不再卡在半空）
  - 点面板以外自动收回；自动弹出 5 秒无操作收回
  - 华为 FreeBuds Pro 5 / FreeClip 2 + vivo / iQOO 双品牌支持

运行：双击 run.bat（需 Python 3.10+ 与 PySide6）
打包：双击 build.bat（需 PyInstaller 6+）
